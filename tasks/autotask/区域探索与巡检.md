# 区域探索与地图巡检

`area_explore` 探索新区域或复勘已有区域。`map_patrol` 在已保存的通行图上巡检。两类任务共用 URAN 的 `uran.tasks.command.v1`、控制权租约、底盘速度命令和操作事件。设备型号、场地名称和传感器话题由装配配置提供。

## 任务参数

| 参数 | 用途 |
| --- | --- |
| `map_id`、`frame_id`、`resolution_m` | 同一张 SLAM 底图使用稳定的标识、地图坐标系和通行栅格分辨率。默认坐标系为 `map`，通行栅格默认 0.5 米。 |
| `reference_mode: local` | 使用 SLAM 的米制坐标。航点用 `position_m: [x, y]`，可选 `boundary_m` 为地图坐标的 Polygon。省略边界时探索起点连通的区域。 |
| `reference_mode: geographic` | `geofence` 为 WGS84 GeoJSON Polygon，坐标按经度、纬度排列，支持内环。航点可用 `lat`、`lon` 或 `position_m`。已有地图配准可由 `georeference` 提供。 |
| `resurvey` | 适用于探索。普通探索补充未知区域，已确认可通行的区域可覆盖旧红区。显式复勘允许反复确认的固定障碍将旧绿区改红。 |
| `waypoints`、`visit_order` | 巡检需要唯一的 `waypoint_id`。默认 `nearest` 按连通绿区内的路径距离依次选点，`given` 按下发顺序执行。 |

室内探索可使用以下 `parameters`。同一张图的巡检指定 `task_type: map_patrol` 并添加 `waypoints`。

```json
{"map_id":"floor_1","frame_id":"map","reference_mode":"local","resolution_m":0.5,
 "boundary_m":{"type":"Polygon","coordinates":[[[0,0],[6,0],[6,4],[0,4],[0,0]]]}}
```

## 定位、通行与结果

里程计在两次激光修正之间提供连续位姿。观测节点使用带时间戳的地图到里程计 TF，或用 SLAM 机身位姿与同一时刻插值的里程计计算修正。地形点、机身和航点投到同一个米制坐标系。定位突变会停车并重新规划。

地理模式按采集时间配对 GNSS 与地图位姿，用有足够位移且相互一致的样本估计平移与朝向。重新经过同一地点时可更新早期观测。配准前的活动半径由 `startup_radius_m` 控制，默认 2 米。配准后若处于圈外，优先沿已确认可通行的路径回圈。室内模式直接使用地图位姿。

地形观测须同时确认整个机身活动范围内的地面连续、高差、坡度和净空。激光扫描用于局部避障。巡检只读底图，遇阻先绕行，仍不可达则记录原因，继续其余航点。整体感知或定位超时会等待恢复。任务结果位于 `/uran/runtime/events` 的 `result_json` 中。

- 探索的 `map.green`、`map.red` 均按 `[y, x_first, x_last]` 编码，左右端点均计入。红区包含固定障碍和未验证区域。`fixed_obstacles` 与 `unverified_area_m2` 保留两者的区别。本地模式返回 `boundary_m`，地理模式返回 `boundary` 和 `georeference`。
- 巡检用 `visited`、`missed`、`pending` 回报航点。部分到达时 `outcome` 为 `partial`，全部不可达时为 `no_waypoint_reached`。

## 装配与迁移

`uran_plugins` 提供任务策略、定位、导航以及可选的厂商适配器。`uran_ros2_adapter` 提供 ROS 观测节点和通用分发。将这两个仓库的对应改动一起交付。任务 worker 依赖带有地图配准和地形接口的定位、导航 wheel，ROS 节点使用安装了 rclpy 的系统 Python。worker 需要 Python 3.10 或更高版本。

在任务实例的 `message_types` 中登记 `uran.tasks.command.v1`、`uran.sensors.observation.v1` 和 `uran.operations.cancel.v1`，任务能力为 `tasks.area_explore`、`tasks.map_patrol`。在 `worker_config` 设置 `arbiter_instance`、运动命令的 `body_frame` 和 `mapping`，控制仲裁器照常按底盘组件选择运动插件。地图任务通过观测契约接入传感器，可独立于旧航点任务的导航后端装配。

```yaml
arbiter_instance: arbiter
body_frame: base_link
mapping:
  map_database: /var/lib/uran/maps.sqlite3
  manage_slam: false
  terrain:
    body_radius_m: 0.40
    body_height_m: 0.45
    max_step_m: 0.06
    max_slope_deg: 15
    terrain_sample_m: 0.10
    terrain_range_m: 3.0
```

上述地形数值为开发默认值。换机时应填写含附件和运动包络的实测尺寸、可跨越高差与可接受坡度。SLAM 底图与地理配准可共用。SQLite 按地形参数分别保存通行区，条件相同的设备可以共用同一层。旧数据库若缺少当时的地形参数，可用 `mapping.legacy_terrain` 指明旧参数后接续旧层。参数未知时仍可复用已存的激光地图，新设备通过探索建立自己的通行层。

矩形底盘可在 `worker_config.straight_drive` 设置 `robot_length_m`、`robot_width_m`、每侧的 `safety_margin_m`、绕机身中心的 `turn_radius_m`。扫描须经 TF 换到机身中心。直行检查制动距离内的通道，原地转向检查整个圆盘。雷达视野有限时，地图任务用近期地面与净空观测补足转身范围。CyberDog2 的取值在 `uran_profiles/profiles/cyberdog2/autotask.json`。

**标准 ROS 2 设备**。外部 SLAM 管理建图、保存和重定位，`mapping.manage_slam` 设为 `false`。先让 SLAM 装载任务对应的地图，再在已加载 ROS 环境和适配器的终端运行以下命令。话题名称和 TF 坐标系按设备配置替换。

```bash
ros2 run uran_ros2_adapter map_observations --ros-args \
  -p device_id:=robot_01 -p component_id:=base -p instance_id:=mission \
  -p map_id:=floor_1 -p reference_mode:=local -p map_frame:=map \
  -p body_frame:=base_link -p ground_frame:=base_footprint \
  -p odom_topic:=odom -p scan_topic:=scan -p depth_topic:=depth/points
```

标准输入使用 `Odometry`、`LaserScan`、带采集时间的 XYZ `PointCloud2`，地理模式可添加 `gps_topic` 订阅 `NavSatFix`。地面参考系原点位于机身下方的地面。点云所属坐标系的原点与传感器光心不同时，用 `depth_origin_frame` 指明光心。外部发布者也可直接发 `uran.sensors.observation.v1`。ROS 信封指定接收插件，正文的 `source` 指明设备和观测组件。

**CyberDog2 装配**。ROS 的 Python 环境需要能导入 `uran_cyberdog2_plugin.map_sensors` 和厂商的 `protocol` 消息。设置 `mapping.manage_slam: true`，观测节点通过以下参数在任务事件到达时启动、保存和重定位原生激光图。此时 `map_id` 由任务下发。节点命名空间、里程计话题和 TF 按实机标定配置。

```bash
ros2 run uran_ros2_adapter map_observations --ros-args \
  -p device_id:=robot_01 -p component_id:=base -p instance_id:=mission \
  -p odom_topic:=visual_odom -p ground_frame:=visual_odom -p scan_topic:=scan -p tof_topic:=head_tof_payload \
  -p sensor_adapter:=uran_cyberdog2_plugin.map_sensors:bind_sensors \
  -p slam_adapter:=uran_cyberdog2_plugin.map_sensors:LaserSession
```

厂商适配器按左右机头 ToF 的采集时间解码回波。解码后的光心和点位于厂家外参的父坐标系，参数 `tof_mount_frame` 默认为 `base_link`。可用 `rear_tof_topic` 订阅机尾的两路 ToF，按消息中的传感器坐标系和安装 TF 投影。地理模式可配置标准 `gps_topic` 或厂商的 `receiver_topic`。同一 GNSS 接收机选用一个入口。已知地图先重定位再执行任务，首次建图在设备确认保存后提交通行栅格。

`map_pose` 携带 `map_id`、米制 `x`、`y`、`yaw_deg` 及 `localization_revision`。本地地图要求 `odometry_fused: true`。地形可以选用 `depth_rays` 的光心和终点，或经相同设备包络评估的 `terrain_cells`。预分类生产者应携带 `terrain`、`resolution_m` 和采集时间，接收方只采纳与当前通行层一致的结果。

## 五米观测范围与实时位置

建图按采集时机身中心到目标的水平距离计量，半径为 5 米。超出范围、被遮挡或缺少有效回波的位置保留未知，走近后可以继续探索。已经测过的栅格保留。地形参数 `terrain_range_m` 另行限制评估地面和净空的可信射线长度，开发配置为 3 米。任务结果的 `unverified` 逐行记录尚待确认的位置，巡检沿用红色禁行遮罩。

`position` 随任务进度上报地图坐标 `x`、`y`、`yaw_deg`、采集时间 `timestamp_ns` 和新鲜度 `fresh`。室内通过 SLAM 和里程计获得位姿，室外完成地图与 GNSS 配准后，同一位置附带 WGS84 的 `latitude_deg`、`longitude_deg`。

室内视觉里程计通过标准 `nav_msgs/msg/Odometry` 接入。以下命令在 CyberDog2 板端的 URAN 开发目录运行，`ROBOT_NS` 取设备 ROS 命名空间，`MAP_DIR` 取本次地图的绝对目录。先加载本机 ROS、厂商与 URAN 工作区环境，再打开 RealSense 的校正双目、IMU 和深度图话题。在起点平地保持静止，等地面参考和视觉跟踪建立。

```bash
src=uran_plugins/motion/cyberdog2/visual_odometry
cmake -S "$src" -B build/visual_odometry -DCMAKE_BUILD_TYPE=Release
cmake --build build/visual_odometry -j2
bash "$src/indoor_mapping.bash" "$ROBOT_NS" "$MAP_DIR"
```

启动脚本先在设备端加载建图节点。扫描融合和地面观测共用一份深度图。连续收到三帧新鲜视觉位姿后，SLAM 开始接收融合扫描，并从预测位姿出发做局部匹配。这台设备的室内视觉配置关闭了每帧的大范围相关搜索。它读取本机 CycloneDDS 的网络配置，创建建图套接字时用 `sudo -n sysctl` 临时将 Linux 接收缓冲上限调到 4 MiB，节点就绪后恢复原值。按 Ctrl+C 将占用图和重定位图保存到指定目录。默认开发观测输出在 `$ROBOT_NS/uran_survey/observations`。需要将观测交给运行中的任务时，可设置 `OBSERVATION_TOPIC=/uran/runtime/dispatch` 和任务使用的 `DEVICE_ID`。

MiVINS 依据已标定的双目基线估计米制位移，使用 IMU 给出重力方向和帧间姿态约束。准备脚本读取本机外参及校正图像的投影矩阵，用起点深度拟合地面。输出 `visual_odom` 的子坐标系为 `base_link`，原点位于起点地面，时间戳来自双目曝光。每次重启视觉里程计都应重新建图或重定位。使用其他设备时，建图节点接入该设备提供的机身里程计和地面参考。

单独调试融合扫描时使用设备命名空间。深度相机和 ToF 的平面回波参与 SLAM 定位，两类传感器的立体观测同时用于占用建图。

```bash
ros2 run uran_ros2_adapter fused_scan --ros-args -r __ns:="$ROBOT_NS" \
  -p odom_topic:=visual_odom -p ground_frame:=visual_odom \
  -p depth_image_topic:=camera/depth/image_rect_raw -p depth_camera_info_topic:=camera/depth/camera_info \
  -p sensor_adapter:=uran_cyberdog2_plugin.map_sensors:bind_tof -p rear_tof_topic:=rear_tof_payload \
  -p unknown_range:=zero
```

机头雷达窗旁的标签移除后，原始扫描恢复了正前方回波。当前设备在机身中心 5 米范围内保留有效激光回波，包括近处障碍物。激光缺测方向由时间和高度匹配的深度或 ToF 实测点补充，其余方向保持未知。

`python3 -m uran_cyberdog2_plugin.slam_params "$MAP_DIR/config" "$MAP_DIR" --odom-topic visual_odom` 从本机厂商模板生成建图和重定位配置。厂商 launch 分别通过 `mapping_params_file` 和 `localization_params_file` 装载对应 YAML，两个节点均订阅设备的 `scan_fused`。通行控制继续接低延迟 `scan`。任务运行时通过 `map_observations` 把里程计和 SLAM 配准到同一张图。使用厂商位姿话题时，设置 `pose_topic:=dog_pose` 和 `map_frame:=laser_odom`。

```bash
ros2 run uran_ros2_adapter survey_map --ros-args -r __ns:="$ROBOT_NS" \
  -p map_id:="$MAP_ID" -p map_frame:=laser_odom -p pose_topic:=dog_pose \
  -p coverage_file:="$MAP_DIR/coverage.sqlite"
ros2 run nav2_map_server map_saver_cli -t "$ROBOT_NS/survey_map" -f "$MAP_DIR/occupancy"
```

本机纸板实测发现激光近距读数偏短。上述参数对雷达窗起算 1 米内、落在已标定相机视野中的回波做深度复核。两次深度实测都比投影点远 5 厘米以上时，建图可采用同步扫描平面的实测替代点。相机缺测的位置在重叠区域暂记未知，同高度的近距 ToF 可以保留真实障碍回波。底盘避障继续读取原始 `scan`。其他设备可按实测选择是否启用复核。

启动 `map_observations` 时指定当前地图、同一地图坐标系，以及已标定的深度相机和 ToF 适配器。`map_observations` 和 `survey_map` 默认通过同一命名空间的 `survey_surfaces` 对接。分属不同命名空间时，将两者的 `surface_topic` 设为同一个绝对话题名。

RViz 和地图导出使用 `survey_map`。每张地图使用独立目录，保存观测覆盖、占用图和厂商定位图。已有地图巡检装载保存的占用图，使用同一场景的定位图计算当前位姿。

占用图中的白色也包括重复观测到的地面。机器狗运动时，任务的通行层另行检查地面连续性、坡度、台阶和机身净空。
